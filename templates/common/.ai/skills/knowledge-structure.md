# 知识归属规则

当前知识在 `.ai/knowledge/`,过程记录在 `.ai/memory/`。写入前先判断归属:**每条知识只有一个归属**,不在两处各写一份。

## 归属表

| 知识类型 | 归属 |
|---|---|
| 只在某个入口体现的行为 | 入口页 `knowledge/entries/<分组>.md` |
| 多个入口共用的业务规则 | 领域页 `knowledge/domains/<领域>.md` |
| 无对外入口的后端行为 | 领域页 |
| 实体、数据归属、状态流转 | 领域页 |
| 接口形状(字段、类型、状态码等) | 项目契约文件,页面只引用 |
| 会约束后续实现的决策 | `knowledge/decisions/` |
| 需求点状态与顺序 | `knowledge/iterations.md` |
| 命令、代码与提交约定 | `knowledge/conventions.md` |
| 做了什么、关键决策、下一步 | `.ai/memory/session-log.md` |

## 契约描述形状,入口页描述语义

- **形状**归契约文件:字段、类型、取值范围、必填性、状态码。
- **语义**归入口页:业务规则、错误含义、副作用、幂等性、调用顺序。
- 入口页不复制契约里的字段表,只写契约位置并引用。

## 提升规则

1. 规则首次出现时写在入口页。
2. 第二个入口也用到同一规则时,把它提升到领域页,入口页原处改为链接。
3. 入口页引用领域规则时**只放链接,不复制内容**;摘要会变成第二份事实源,需要额外同步。

## frontmatter 规范

知识页用 frontmatter 提供机器可读字段,供 `ai-memory kb build` 生成索引与横向视图。只支持标量与字符串数组两种值,键用小写下划线。

| 页类型 | 必填 | 可选 |
|---|---|---|
| 入口页 `type: entry` | `group`、`form`、`summary` | `contract`、`domains`(数组) |
| 领域页 `type: domain` | `name`、`summary` | — |
| 决策页 `type: decision` | `status`、`date` | `superseded_by` |

- `domains` 填领域页的 `name`,脚本据此反查生成领域页的「关联入口」。
- `contract` 填契约文件路径,汇总为领域页的「相关接口」。
- 缺 frontmatter 或缺必填字段的页会被跳过并列出,不影响其他页生成。

## 生成区块

`<!-- ai-memory:generated:<名称>:start -->` 与 `:end` 之间的内容由 `ai-memory kb build` 重写,**不要手工编辑**;标记之外的内容脚本一律不碰。

标记缺失、重复或顺序错误时脚本保守失败,不会覆盖整个文件。

`ai-memory kb check` 只读校验 frontmatter、知识层内部链接、悬空领域/决策引用与索引是否过期;有问题时退出码为 1。领域页没有关联入口是合法状态(无对外入口的后端行为),不会报错。

## 写入纪律

- 写成当前状态,不写「本次新增」「改为」这类相对表述。
- 领域页下半部分的横向视图由 `ai-memory kb build` 生成,不要手工总结。
- 用不到的章节整段留空,不编造内容填满模板。
