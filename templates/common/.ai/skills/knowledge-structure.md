# 知识归属规则

当前知识在 `.ai/knowledge/`,过程记录在 `.ai/memory/`。写入前先判断归属:**每条知识只有一个归属**,不在两处各写一份。

## 归属表

| 知识类型 | 归属 |
|---|---|
| 只在某个入口体现的行为 | 入口页 `knowledge/entries/<分组>.md` |
| 多个入口共用的业务规则 | 领域页 `knowledge/domains/<领域>.md` |
| 无对外入口的后端行为 | 领域页 |
| 实体、数据归属、状态流转 | 领域页 |
| 接口形状(字段、类型、状态码等) | 项目契约文件,页面只引用 |
| 会约束后续实现的决策 | `knowledge/decisions/` |
| 需求点状态与顺序 | `knowledge/iterations.md` |
| 命令、代码与提交约定 | `knowledge/conventions.md` |
| 做了什么、关键决策、下一步 | `.ai/memory/session-log.md` |

## 契约描述形状,入口页描述语义

- **形状**归契约文件:字段、类型、取值范围、必填性、状态码。
- **语义**归入口页:业务规则、错误含义、副作用、幂等性、调用顺序。
- 入口页不复制契约里的字段表,只写契约位置并引用。

## 提升规则

1. 规则首次出现时写在入口页。
2. 第二个入口也用到同一规则时,把它提升到领域页,入口页原处改为链接。
3. 入口页引用领域规则时**只放链接,不复制内容**;摘要会变成第二份事实源,需要额外同步。

## 写入纪律

- 写成当前状态,不写「本次新增」「改为」这类相对表述。
- 领域页下半部分的横向视图(关联入口、相关接口、需求点历史)由脚本生成,不要手工总结。
- 用不到的章节整段留空,不编造内容填满模板。
