## 实现期发现的问题

六个只有真正跑起来才会暴露的缺陷。其中两个是测试自身的问题,而且互相掩盖。

**git 折叠未跟踪目录,让契约门禁失效**
`git status --porcelain` 把新增文件折叠成 `?? src/`,匹配不上 `src/api/**`。一个专门抓「加了接口没写契约」的门禁,恰恰漏掉所有新增文件。改用 `-uall`。

**迁移不幂等,部分失败后彻底卡死**
写入一半失败后重跑,目标文件哈希已变,被判成「用户改过」而跳过,项目永久停在半迁移状态。改为先算内容判 noop、再判改造,并给追加操作加去重。

**「需求集合」表头被当成需求点**
那张表的表头同样是四列,只按列数与首列过滤就混了进去——全新项目首页显示「1 个需求点,状态:备注」。改为按章节定位,并抽成 `src/iterations.js` 共享,顺带修掉 `gate-ready` 里同样的脆弱性。

**空索引生成表头,新项目一上来就是脏的**
没有知识页时仍生成表头与分隔行,与模板里的空区块永远对不上,`kb check` 立刻报「索引过期」。空即空。

**门禁的兜底超时被 unref,反而把编辑挂住**
调用方不关 stdin 时定时器永不触发。一个用来防故障的机制,自己成了故障——正是它想防的那类。

**测试联网下载,又被失效的隔离掩盖**
导出测试真的从 CDN 拉了 3.4MB 并写进真实缓存;而缓存隔离写在 `afterEach` 里,第一个用例之后就失效,后续测试落回那个缓存,于是降级路径看起来一直是绿的。一个 bug 制造污染,另一个让污染看起来正常。

## 反复出现的模式

**适配层不是薄包装。** R1、R2、R3 各有一次:改完 `.ai/skills/` 之后,靠事后 grep 才发现 `.claude/` 或 `.agents/` 里藏着一条矛盾的规则。R7 把这件事交给了测试。

**加扫描守卫时默认排除规范文档与版本历史。** 踩了三次:README 的版本历史要写出「移除了 Superpowers」、`knowledge-structure.md` 要写出生成区标记格式、v0.6.0 的历史升级说明要保留原文。文档*描述*某物 ≠ 代码*依赖*某物。

**npm 的写操作会重排 `package.json`。** `npm version` 与 `npm install` 各展开过一次手写的紧凑格式,都要回退。

## 明确没做

**需求点历史横向视图** — 生成它需要每个需求点登记影响了哪些领域,等于给每次开发加一道手工登记,与「知识体量随系统规模增长而非开发次数增长」直接冲突。

**把沉淀升格成 skill 或 hook** — 需要先知道什么样的规则值得升格,而这要真实用过几轮才有依据。现在设计它,大概率造出一个没人用的登记流程。

**接入 CI** — 三条命令都已有退出码契约,加一行即可,但那是项目自己的决定。

**方案 §7 的其余暂缓项** — critic/review 轮次上限、会话加载体量检查、用户级记忆移出仓库、wiki 静态站选型(已由 `kb export` 以另一种形态覆盖)。
